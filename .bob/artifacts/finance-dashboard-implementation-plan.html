1. Project Structure

Use Vite + React 18 + TypeScript for fast dev server, small bundle, and modern tooling.

finance-app/ ├── public/ │ └── vite.svg ├── src/ │ ├── assets/ # static assets (logos, icons) │ ├── components/ # presentational UI components │ │ ├── charts/ # chart-specific components │ │ ├── dashboard/ # dashboard-specific composites │ │ ├── layout/ # header, sidebar, footer │ │ └── ui/ # reusable primitives (Button, Card, Select, Spinner, Alert) │ ├── config/ # app-wide constants, ticker map, time windows │ ├── context/ # React Context providers (theme, data) │ ├── hooks/ # custom hooks (useFinanceData, useTimeWindow, useDebounce) │ ├── services/ # data fetching & normalization layer │ │ ├── finance-api.ts # Yahoo Finance wrapper (yahoo-finance2) │ │ ├── transformers.ts # raw → UI-shaped data │ │ └── cache.ts # in-memory + localStorage cache │ ├── store/ # state management (Zustand) │ │ ├── dashboardStore.ts # global dashboard state │ │ └── uiStore.ts # UI-only state (modals, toasts) │ ├── types/ # TypeScript interfaces │ │ ├── finance.ts # Quote, HistoryPoint, CompanyProfile │ │ └── ui.ts # ViewMode, TimeWindow, LoadingState │ ├── utils/ # pure helpers (formatters, date math, validation) │ ├── views/ # page-level components (route targets) │ │ ├── DashboardView.tsx # main dashboard (3 tabs) │ │ └── CompanyDetailView.tsx # future: user-selected company │ ├── App.tsx # root component, providers, routing │ ├── main.tsx # entry point │ └── index.css # global styles (CSS variables, reset) ├── tests/ # co-located or separate test tree │ ├── services/ │ ├── components/ │ └── utils/ ├── .github/workflows/ # existing CI ├── index.html ├── package.json ├── tsconfig.json ├── vite.config.ts ├── vitest.config.ts └── README.md

Why this layout? Clear separation: services/ owns external I/O, components/ owns rendering, store/ owns mutable state, hooks/ owns reusable logic, views/ owns routing targets. Scales cleanly when Part 2 adds the user-selected company feature.

3. Data Service Abstraction

3.1 Interface (src/services/finance-api.ts)

export interface FinanceApi {
  getQuotes(tickers: string[]): Promise<Quote[]>;
  getHistory(ticker: string, range: TimeRange): Promise<HistoryPoint[]>;
  getProfile(ticker: string): Promise<CompanyProfile>;
}

export const yahooFinanceApi: FinanceApi = {
  async getQuotes(tickers) { /* yahoo-finance2 quoteSummary */ },
  async getHistory(ticker, range) { /* yahoo-finance2 chart */ },
  async getProfile(ticker) { /* yahoo-finance2 quoteSummary modules */ },
};

3.2 Normalization Layer (src/services/transformers.ts)

Raw Yahoo responses → UI-friendly shapes:

export interface Quote {
  symbol: string;
  shortName: string;
  regularMarketPrice: number;
  regularMarketChange: number;
  regularMarketChangePercent: number;
  currency: string;
  marketState: 'REGULAR' | 'PRE' | 'POST' | 'CLOSED';
}

export interface HistoryPoint {
  date: string;        // ISO date
  close: number;
  volume: number;
}

export interface CompanySnapshot {
  quote: Quote;
  history: HistoryPoint[];  // last 7 days or quarter
}

3.3 Caching Strategy (src/services/cache.ts)

  • In-memory (Map) keyed by ${ticker}:${range} — 30 s TTL for quotes, 5 min for history
  • localStorage persist last successful payload for offline-first feel
  • Stale-while-revalidate: serve cache immediately, refresh in background

Why an interface? Swappable implementation — can replace yahooFinanceApi with a backend proxy, mock service for tests, or different provider without touching components.

Recharts config highlights:

  • ResponsiveContainer for fluid sizing
  • XAxis with tickFormatter for short dates
  • Tooltip shared across series, custom formatter for currency
  • Legend clickable to toggle series
  • Color palette: IBM blue (#0066cc), competitors distinct hues (MSFT blue, ORCL red, SAP blue, CRM orange)

Yahoo Finance caveat: Browser CORS blocks direct yahoo-finance2 calls. Two pragmatic options:
1. Vite dev proxy (vite.config.ts server.proxy) to a lightweight Node/Express proxy you control
2. Mock mode for workshop — finance-api.ts returns deterministic fixture data when import.meta.env.VITE_MOCK_FINANCE === 'true' (recommended for reproducible demos)

5. State Management Strategy

Choice: Zustand — minimal (~1 KB), TypeScript-first, no provider boilerplate, works outside React.

5.1 Dashboard Store (src/store/dashboardStore.ts)

interface DashboardState {
  // data
  snapshots: Map<string, CompanySnapshot>;
  // ui
  activeWindow: TimeWindow;        // '1D' | '7D' | '1Q'
  selectedTickers: string[];       // default 5, user can add (Part 2)
  loading: Set<string>;
  errors: Map<string, Error>;
  // actions
  setActiveWindow: (w: TimeWindow) => void;
  addTicker: (ticker: string) => void;
  removeTicker: (ticker: string) => void;
  refreshAll: () => Promise<void>;
  refreshOne: (ticker: string) => Promise<void>;
}

5.2 UI Store (src/store/uiStore.ts)

Toasts, modal visibility, sidebar collapse — purely ephemeral UI state.

Why not Redux / Context? Zustand avoids provider nesting, enables selector-based subscriptions (components re-render only on relevant slice changes), and is trivial to test (just call actions on the store).

6. Error Handling

LayerStrategyUser-Facing
Network / APIRetry 2× with exponential backoff (1 s, 2 s)Toast + inline retry button on card/chart
Invalid tickerValidate via getProfile before addingInline error under input: "Symbol XYZ not found"
Partial failurePer-ticker error state; others still renderCard shows "—" with error icon, tooltip shows detail
Rate limit (Yahoo)Cache + dedupe requests; queue if >5 concurrentBanner: "Rate limited — showing cached data"
Missing data pointsInterpolate or show gap in chartChart renders with null gaps; tooltip says "No data"

Error boundary: Wrap each chart/card in a React error boundary so one crashing component doesn't blank the whole dashboard.

8. Local Validation Steps

  1. Install: npm install

9. GitHub-Driven Feature Evolution

9.1 Branch & PR Convention

  • feature/initial-finance-dashboard — initial delivery (Part 1)
  • feature/user-selected-company-chart — Part 2 enhancement
  • fix/chart-data-normalization — bug fixes
  • bob/<short-desc> — branches pushed by Bob autonomously

9.2 PR Template (already in repo)

Enforces: Summary, Motivation, Change Type, Bob Collaboration Notes, Validation commands, Feature Request Alignment, Screenshots, Risks.

9.3 Issue → Implementation Flow

  1. Human files issue (e.g., "Add graph for user-selected company")
  2. Bob fetches issue via GitHub CLI or API (gh issue view 123 --json)
  3. Bob analyzes repo: reads src/store/dashboardStore.ts, DashboardView.tsx, finance-api.ts
  4. Bob plans: add selectedTicker to store, TickerSelect component, new chart panel, validation
  5. Bob implements in feature branch, runs npm test && npm run build
  6. Bob pushes branch, creates/updates PR with generated description (diff summary + test results)
  7. CI runs automatically; maintainer reviews & merges

9.4 Extensibility Hooks Built In

  • Ticker registry in config/tickers.ts — add/remove companies without code changes
  • TimeWindow enum — add "1M", "1Y" by extending enum + config
  • ChartSeries adapter — new chart types only need a ChartSeries producer
  • FinanceApi interface — swap Yahoo for Alpha Vantage, Polygon, or internal proxy

Key principle: Every feature arrives via a GitHub issue/PR. Bob never commits directly to main — always works on a feature branch, validates, then opens/updates a PR. This gives full traceability: Issue → Branch → Commits → PR → CI → Merge.
